# План по фазам

Текущая фаза: **2 — локальный каркас, в работе**. Шаг 2.1 (минимальный API) ожидает ручной проверки.

Исходный ориентир «два дня» сохраняем как оценку MVP, а не обещание срока. Двигаемся по проверяемым результатам; каждую фазу закрываем вместе. Если фаза не помещается в одну понятную ручную проверку, перед реализацией делим её на меньшие этапы.

Статусы: `не начата` → `в работе` → `ожидает ручной приёмки` → `принята`. Неуспешная проверка оставляет фазу в работе. Автоматические проверки не заменяют подтверждение пользователя.

## Как проходим каждый этап

Полный продукт описан в [README](../README.md), технические требования — в [спецификации](spec.md). Фазы делят работу над этим продуктом; объём исходного задания не сокращается.

Перед реализацией выбираем один небольшой результат внутри фазы. Агент объясняет, какие данные проходят через код и как увидеть результат; затем реализует его, выполняет проверки и отчитывается. Пользователь повторяет короткий сценарий руками. После обсуждения и подтверждения начинаем следующий шаг. Если понятие или результат пока непонятны, остаёмся на этом шаге и разбираем его.

Для каждого отчёта нужны: изменённые файлы, фактические результаты команд, инструкция ручной проверки с ожидаемым результатом, краткое объяснение нового понятия и оставшиеся ограничения. Примеры и упражнения берём из самого проекта; отдельный учебный фреймворк не строим.

**Статус:** не начата. Исходный пункт 1.8.
